Политика конфиденциальности I Ching Oracle

Последнее обновление: 20 марта 2026

Эта политика описывает, как Android-приложение I Ching Oracle и связанный backend обрабатывают данные во время внутреннего dogfood- и internal testing-использования.

1. Что это за продукт

I Ching Oracle это мобильное приложение для получения reading на основе вопроса пользователя, выбранного метода гадания и интерпретации, возвращаемой backend-сервисом. Приложение поддерживает локальный журнал, переключение языка, mock/live-режимы и developer-проверку staging health.

2. Какие данные обрабатываются локально на устройстве

  • текст вопроса, выбранный метод и line values, если пользователь делает reading;
  • сохранённые результаты readings и локальная история журнала;
  • настройки приложения: язык, runtime mode, base URL, ambient music, onboarding state;
  • локально сгенерированный device ID, который нужен backend для анонимной device session.

3. Какие данные отправляются по сети

В режиме live приложение может отправлять на настроенный backend-endpoint:

  • текст вопроса;
  • locale;
  • метод reading;
  • line values, если они используются выбранным методом;
  • локально сгенерированный device ID.

При ручном /health preflight вопрос не отправляется. По умолчанию приложение использует HTTPS staging URL, но в developer-настройках base URL можно переопределить вручную для тестирования.

4. Как backend использует данные

  • создаёт или продлевает анонимную device session;
  • вычисляет primary и relating hexagram;
  • запрашивает AI-интерпретацию в live-режиме;
  • возвращает reading и correlation/debug headers;
  • при включённом PostgreSQL может сохранять safe audit record с request ID, anonymous ID, locale, методом, номерами гексаграмм, changing line indexes, provider/fallback-метаданными, prompt metadata, latency и timestamp.

Backend-аудит намеренно не сохраняет сырой пользовательский вопрос в PostgreSQL audit-таблице.

5. Кому данные могут передаваться

  • инфраструктуре backend, размещённой в DigitalOcean, если используется live-режим или staging health check;
  • OpenAI через backend только для генерации live-интерпретации, если соответствующий AI-провайдер включён;
  • не передаются рекламным SDK, брокерам данных и платёжным провайдерам, потому что такие интеграции в текущем scope отсутствуют.

6. Что приложение не запрашивает

Текущая Android-сборка не запрашивает и не использует:

  • контакты, телефонную книгу, SMS или звонки;
  • геолокацию;
  • камеру или микрофон;
  • платёжные данные, подписки и in-app billing;
  • рекламный идентификатор, рекламные SDK и персонализированную рекламу;
  • аккаунты пользователей внутри приложения.

7. Хранение и удаление

  • локальная история readings и настройки хранятся на устройстве до очистки истории, сброса app data или удаления приложения;
  • server-side safe audit хранится только для операционных и диагностических целей и не содержит сырого вопроса;
  • в приложении нет пользовательских аккаунтов, поэтому account deletion flow не применяется.

8. Безопасность

Для live-режима предполагается использование HTTPS endpoint и app-private storage на устройстве. Однако developer может вручную указать другой base URL для dogfood- или staging-тестирования; такая конфигурация контролируется пользователем или командой разработки.
